# Pedestrians block API probes

These small experiments support [PD-BLOCK.md](../../../farnell/reviews/PD-BLOCK.md). They are not included by the normal Kleine build, do not modify `include/klang.h` or `include/klang/pd.h`, and do not replace the validated Pedestrians source. Proposed names are kept under `block_trial` to avoid presenting them as released APIs.

[prototypes.h](../../../../experiments/klang/pd-block/prototypes.h) provides the clock, proposed metro, developer-owned and inherited clocks, an automatic buffer event, an always-empty default, a self-disabling default, and an automatic sample-entry alternative. [probe.cpp](../../../../experiments/klang/pd-block/probe.cpp) exercises their behaviour through real Klang dispatch. [results.json](../../../../experiments/klang/pd-block/results.json) records measurements and source hashes, generated by [report.py](../../../../experiments/klang/pd-block/report.py).

On 15 September 2026, MSVC 19.51 with `/std:c++17 /O2` passed:

- Lifecycle checks: first boundary, default retirement, always-empty handler, 0/1/64/128 sizes, disable/re-enable/resize, buffer preparation frequency, and phase persistence across 100 + 28 + 3 samples.
- Typed member callback and captured-lambda forms; fractional size rejection; half-open deadline intervals and multiple metro events in a block.
- **72 sample-identical audio comparisons** with the existing Pedestrians implementation: 2 rates (48/44.1 kHz), 2 recipes (continuous/stop-restart), 3 host partitions (`64`, repeating `1,3,17,79,100,257`, and `1024`), and 6 implementation/evaluation combinations. Buffers also split at external control events.
- **4 sample-identical comparisons with cached PD 0.55.2 WAVs**, covering the two rates and recipes. These are separately checked against the unchanged reference-source hashes.
- An expected negative check at each rate/recipe: an automatic event implemented only in `process(buffer)` is skipped during nested signal evaluation. This establishes a limitation, not a passing implementation for nested use.

The sample-timed callback baseline (`IdealPedestrians`) has the same output for the default 100 ms interval at 48 kHz, where that period is exactly 75 blocks. It differs at 44.1 kHz. The report retains its raw residual as evidence that changing timing can defeat sample comparison; no listening or perceptual acceptance claim follows from that value. The paper now prefers Chris's conditional `if (metro(100))` presentation; these existing probes do not yet implement or validate that revised API.

The probe uses heap-owned sound instances as Kleine does, since Klang's plugin controls/presets make stacking many instances in one test function unnecessarily large. It does not measure steady-state CPU/memory cost. It does not test arbitrary block sizes in the underlying PD primitives, live rate changes, external controls arriving midway through a logical PD block, or automatic parent/child clock sharing.

From an x64 Visual Studio developer command prompt, at the repository root:

```text
mkdir build\pd-block
cl /nologo /std:c++17 /EHsc /O2 /wd4244 /wd4305 /Iinclude experiments\klang\pd-block\probe.cpp /Fobuild\pd-block\probe.obj /Febuild\pd-block\probe.exe
python experiments/klang/pd-block/report.py
```

The Python report uses the project's existing [analysis dependencies](../../../../tools/requirements.txt). If the four PD fixtures are absent, build Kleine Release and populate them first:

```text
python tools/render_artificial.py --cases pedestrians pedestrians-controls
python tools/render_artificial.py --rate 44100 --cases pedestrians pedestrians-controls
```

Scratch binaries, raw float audio and compiler files stay under `build/pd-block`. The report intentionally retains the small experimental sources and JSON evidence. No book content is read or copied by these probes.
